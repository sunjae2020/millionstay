[2] CRITICAL_FINDINGS 추가 항목 검토
다음 패턴이 코드에 있는지 grep만 해서 발견되면 CF로 추가:

(a) Date 처리 — 시간대 정보 없이 string으로 저장하는 컬럼
    - grep: `text("created_at"|timestamp without time zone`
    - PMS는 호주(AEST/AEDT) + 게스트의 모국 시간대 혼재. 
      체크인/아웃 날짜에 timezone 정보 없으면 1일 오차 발생 가능.

(b) 동시성 — bookings/contracts 생성 시 트랜잭션 사용 여부
    - grep: `db.transaction\(` 사용 횟수
    - booking → contract → invoice 다단계 INSERT가 트랜잭션 밖에서 
      이루어지면 부분 실패 시 데이터 부정합.

(c) Soft delete vs Hard delete 일관성
    - grep: `deletedAt|is_deleted|isActive` 컬럼 사용 패턴
    - 일부 테이블은 soft, 일부는 hard면 cascade 동작 예측 불가.

발견된 것만 CF-013, CF-014... 로 추가. 없으면 "검토 완료, 추가 없음" 보고.

[3] MONEY_AUDIT 보강 — 보존 가치 큰 항목

마이그레이션(Option A 또는 B) 후 재무 정합성 검증용 테스트 케이스.
실제 코드 변경 X, 테스트 정의만:

- TC-M01: 동일 booking으로 생성된 contract의 weekly_rate가 booking의 
  weekly_rate와 정확히 일치하는가 (현재는 real 변환으로 손실 가능)
- TC-M02: 모든 active contract의 line_items 합 = contract.total_rent
- TC-M03: paid invoice의 amount 합 = contract의 누적 결제액
- TC-M04: bond_amount = weekly_rate * 4 불변식이 모든 active contract 
  에서 성립하는가
- TC-M05: Stripe charged amount(cents) = invoice amount * 100 정확 일치

각 TC에 SQL 쿼리 스케치 포함. Phase 2에서 그대로 단위 테스트로 변환 가능.
