# 통합(단체) 청구 — 여러 공간을 임차한 계정의 월 1회 합산 청구

한 계정(`accounts`)이 여러 호실을 임차하는 법인 세입자(예: 재원산업, 계정 #324)는
호실마다 인보이스를 따로 받는 대신 **매월 지정한 날짜에 한 장의 통합 청구서**로
받고 한 번에 납부한다.

## 데이터 모델 — 부모 1 + 자식 N

| | `invoice_kind` | `contract_id` | 역할 |
|---|---|---|---|
| 통합 청구서(부모) | `consolidated` | 없음 | 세입자가 실제로 납부하는 문서. 금액 = 자식 합계 |
| 공간별 인보이스(자식) | `standard` | 있음 | 계약 단위. **GL 전기와 정산(payout)의 정본** |

자식은 `parent_invoice_id` 로 부모를 가리키고, 양쪽 모두 `billing_period`(`YYYY-MM`)를 가진다.

> ⚠️ **집계에서 부모는 반드시 제외한다.** 자식이 매출의 정본이므로 둘 다 더하면 두 번
> 계산된다. `excludeConsolidated()`
> ([artifacts/api-server/src/lib/billing/consolidatedInvoices.ts](../artifacts/api-server/src/lib/billing/consolidatedInvoices.ts))를
> 쓸 것 — 대시보드·리포트·계정 재무 요약에 이미 적용되어 있다.

수납도 같은 원칙을 따른다. 통합 청구서에 `POST /v1/invoices/:id/pay` 를 치면
자식들이 함께 `Paid` 가 되고 **자식 단위로** GL 전기 + 정산 leg 이 생성된다. 부모 자신은
전기하지 않는다.

## 계정별 설정 (관리자 → 계정 상세 → 인보이스 탭)

`accounts` 컬럼 3개 · `PUT /v1/accounts/:id/billing-settings`

| 설정 | 컬럼 | 뜻 |
|---|---|---|
| 통합 청구 사용 | `consolidated_billing_enabled` | 켜면 이 계정의 계약은 월세 크론이 건너뛰고 통합 청구서 생성기가 맡는다 |
| 청구 기준일 | `consolidated_billing_day` (1~28) | 매월 이 날짜로 발행·납기. 29~31은 달마다 없어 제외 |
| 지난달 일할분 이월 | `consolidated_prorate_enabled` | 아래 참고 |

## 일할계산(프로라타) 이월

지난달 **중간에** 입주한 계약은 지난달 임대료가 아직 청구된 적이 없다. 이번 달
통합 청구서에 "지난달 일할분 + 이번 달 전액"을 함께 싣고, 해당 줄의 메모(`description`)와
인보이스 비고(`notes`)에 어느 호실의 어느 기간분인지 남긴다.

```
월세 300,000 · 지난달 15일 거주  →  지난달 150,000 + 이번 달 300,000 = 450,000
```

- 이번 달 중간에 시작하는 계약은 이번 달에 싣지 않는다 — 다음 달 청구서에 이월 일할분으로 들어간다.
- 지난달분 인보이스가 이미 있으면 이월하지 않는다(중복 방지).
- **절사 규칙:** 소수점 없는 통화(KRW·JPY)는 기존 "임대료 납입 청구서" 양식과 같이
  1,000단위 절사한다(월세 350,000 · 7일/31일 → 79,032 → ₩79,000). 그 외 통화는 소수 2자리 반올림.
- 지난달 **전체**가 미청구인 경우(1일 입주인데 청구가 없던 경우)는 이월 대상이 아니다 —
  일할이 아니라 누락이므로 수기로 확인한다.

## 실행 경로

| 경로 | 언제 |
|---|---|
| 크론 `10 3 * * *` (Sydney) | 매일. 통합 청구를 켠 계정 전체 |
| `POST /v1/invoices/consolidated/run` `{ account_id?, year?, month? }` | 관리자 "이번 달 생성" 버튼 |

둘 다 같은 코드이고 **멱등**이다. 같은 (계정, 월)로 다시 돌리면 금액만 재계산하고
중복 발행하지 않는다. 이미 `Paid`/`Void`/`Archived` 인 청구서는 건드리지 않는다.

한 계정에 통화가 다른 계약이 섞여 있으면 첫 계약의 통화로 한 장을 만들고, 통화가
다른 계약은 건너뛴다(결과의 `skipped`). 그 계약들은 공간별 인보이스로 남는다.

## 세입자 포털

`/portal/invoices` 는 통합 청구서를 한 장의 카드로 세우고(배지 = 통합 청구),
카드를 펼치면 **호실별 내역**(호실 · 기간 · 금액, 일할 이월분 포함)과 **공간별
인보이스** 목록을 함께 보여준다. 자식 인보이스는 목록에 따로 서지 않는다 — 같은 금액이
두 번 보이지 않게 하기 위함이며, 납부 버튼은 통합 청구서에만 붙는다.
