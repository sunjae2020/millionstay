# 네이밍 룰 — 고객ID · 폴더 · 파일 · 리포트

서류가 몇 년 치 쌓이면 파일명이 곧 색인이 된다. MillionStay는 고객ID·폴더·파일·
리포트 이름을 **하나의 규칙**으로 짓고, 구현을
[docFileName.ts](../artifacts/api-server/src/lib/documents/docFileName.ts) +
[partyCode.ts](../artifacts/api-server/src/lib/documents/partyCode.ts) 두 곳에만 둔다.
라우트에서 `` `${ref}.pdf` `` 같은 문자열을 직접 조립하지 않는다.

## 1. 고객 ID

```
[테넌트접두사 2] + [YY] + [MM] + [유형 1] + [일련번호 3]
      MH           26    07       C          001      → MH2607C001  (고정 10자리)
```

| 요소 | 규칙 |
| --- | --- |
| 접두사 | 인스턴스별 고정 2자 대문자 — Metheim `MH`, MillionStay `MS`. `PARTY_CODE_PREFIX`로 주입 |
| YYMM | **최초 등록** 연월. 계약·서류가 더 생겨도 불변 |
| 유형 | `C` 개인 / `B` 기업·파트너·B2B |
| 일련번호 | `001~999` → 소진 시 `A01~Z99` 자동 전환 (월 3,573건) |

번호를 받는 대상은 **계정(account)과 연락처(contact)** — 거래 상대다. DB가
`party_codes` 테이블에서 채번한다. **수동 부여 금지, 폐기 번호 재사용 금지.**
동시 요청은 `uq_party_codes_run`에서 부딪히고 진 쪽이 다음 번호로 재시도하므로
번호가 비거나 겹치지 않는다.

유형 판정은 하나의 규칙이다: 사업자등록번호가 있거나 계정 유형이
`Agent`·`Partner`·`ServiceHost`면 기업(`B`), 나머지(세입자·게스트·개인 소유주)와
모든 연락처는 개인(`C`).

번호는 계정/연락처 상세를 처음 열 때 그 자리에서 부여된다. 기존 데이터는 한 번만
백필한다 — 최초 등록 연월 안에서 등록 순서대로 매기므로, 다시 돌려도 과거 번호가
재배치되지 않는다.

```bash
PARTY_CODE_PREFIX=MH DATABASE_URL=… node scripts/backfill-party-codes.mjs --dry
PARTY_CODE_PREFIX=MH DATABASE_URL=… node scripts/backfill-party-codes.mjs
```

## 2. 구문

| 항목 | 규칙 |
| --- | --- |
| `-` 하이픈 | **이름 / 서류이름** 구분, 그리고 사본번호 앞 (`이아람-계약서_20260816-v2`) |
| `_` 언더스코어 | **필드 내부** 단어 연결 (`홍길동_재원산업`), 그리고 **날짜 앞** |
| 공백 | 이름 필드는 금지(`sanitizePartyName()`이 걷어낸다), **서류이름은 허용**(`sanitizeDocName()`) |
| 금지 문자 | `/ \ : * ? " < > \| # % . -` (이름 조각 안에서), 서류이름은 `- _`만 금지 |
| 서류 이름 | **한글 정식 명칭**. 괄호·공백을 살려 서식명을 그대로 적는다 |
| 사람 이름 | **한글이 정본**. 라틴 표기는 성 전체 대문자 — `Sunjae KIM` |
| 성(CJK) | 성 먼저, 붙여쓰기 — `김선재`. [nameFormat.ts](../artifacts/api-server/src/lib/nameFormat.ts)가 저장 시점에 맞춘다 |

서류이름에만 공백을 허용하는 이유는 `민간임대주택 표준임대차계약서
(등록임대사업자)`처럼 법정 서식명을 줄이면 어느 서식으로 발행했는지 파일명만
보고 가릴 수 없기 때문이다. 날짜 앞이 `_`라서 서류이름에 공백이 들어가도
파서가 필드 경계를 잃지 않는다.

한글을 금지하지 않는 이유: 이 시스템의 문서는 대부분 한국어로 발행되고 수신자가
그대로 읽는다. 대신 **고객ID와 스토리지 폴더는 ASCII로 고정**한다(§3) —
Cloudinary public_id가 URL에 실리기 때문이다.

## 3. 폴더

정본 색인은 `documents` 테이블의 `(entity_type, entity_id, doc_type)`이다.
스토리지 경로는 콘솔·백업에서 사람이 훑을 때를 위한 사본이고, 아무도 경로를
되읽지 않는다 — 연결 키는 항상 `documents.id` / `cloudinary_public_id`다.

```
millionstay/                       인스턴스 루트 (테넌트마다 다름)
├── private/                       민감 서류 — authenticated 업로드 + 보존기한
│   ├── account/MH2607B012/        거래 상대는 고객ID 폴더로 모인다
│   ├── contact/MH2607C001/
│   ├── contract/LS000045/         거래 상대가 없는 레코드는 엔티티 번호
│   └── invoice/IV002204/
├── spaces/ · media/ · logos/      공개 자산 (개인정보 아님, 영구 보존)
└── condition/ · work-orders/      현장 사진
```

계정·연락처 서류는 **고객ID 폴더**에 쌓인다(`resolveDocFolder()`). 고객ID에 이미
연월이 들어 있어 폴더 목록이 등록 순서대로 정렬된다. 폴더명에 이름은 넣지
않는다 — 이름은 바뀌지만 번호는 바뀌지 않는다.

번호가 아직 없는 레코드와 나머지 엔티티는 `<엔티티코드 2자><번호 6자리>` 고정
8자로 떨어진다 (`targetFolderId()`).

| 코드 | 엔티티 | 코드 | 엔티티 |
| --- | --- | --- | --- |
| `AC` | 계정 | `WO` | 작업지시 |
| `CT` | 연락처 | `SH` | 서비스 호스트 |
| `LS` | 계약 | `AG` | 에이전트 |
| `IV` | 인보이스 | `OW` | 소유주 |
| `QT` | 견적 | `IN` | 세대점검 |
| `PR` | 건물 | `DS` | 보증금 정산 |
| `SP` | 세대 | `CO` | 회사 서류 |
| `BK` | 예약 | | |

새 엔티티는 `ENTITY_FOLDER_CODES`에 코드를 먼저 등록한다.

## 4. 발행 문서 파일명

```
[임차인이름]-[서류이름]_[발행일 YYYYMMDD][-v사본번호].<확장자>

이아람-민간임대주택 표준임대차계약서 (등록임대사업자)_20260816.pdf
이아람-민간임대주택 표준임대차계약서 (등록임대사업자)_20260816-v2.pdf   (같은 날 재발행)
이아람-청구서_20260816.pdf                            (종류가 다르면 v 표기 없음)
홍길동_재원산업-계약서_20260816.pdf                    (법인 거래처 — 담당자_상호)
공실_402호-견적서_20260816.pdf                        (상대가 특정되지 않는 문서)
```

- **임차인이름** — 그 문서를 받는 거래 상대(임차인·고객). 사람 이름이 없으면
  계정명 → 건물/호실명 순으로 대체하고, 그것도 없으면 `미지정`. 상호를 함께
  남기는 인스턴스에서는 `담당자_상호`가 된다(§6).
- **서류이름** — 아래 표의 **한글 정식 명칭**. 통제 어휘이며 자유 서술 금지.
- **발행일** — 문서 자체의 날짜(청구서 발행일, 수납일, 계약 작성일…). 렌더
  시점이 아니다.
- **사본번호** — 같은 사람에게 같은 날 **같은 서류**를 두 번 이상 발행할 때만
  붙는다. 첫 발행본은 표기 없음, 이후 `-v2`, `-v3`.

**고객ID(§1)는 파일명에서 뺐다.** 받는 사람이 그대로 열어 보는 이름에 내부
번호가 먼저 나오면 읽는 순서가 뒤집힌다. 번호는 §3의 **보관 폴더명**으로
계속 쓰므로 추적성은 그대로다.

### 사본번호는 사람+서류종류+날짜 기준이다

같은 날 계약서 한 장과 청구서 한 장을 내면 서류종류가 다르므로 **둘 다 첫
발행본**이고 표기가 없다. 같은 계약서를 그날 다시 뽑을 때만 `-v2`가 붙는다.
재발행이 예외인데 예외 아닌 쪽에 번호를 다는 것은 거꾸로다.

### 서류이름 표준값

| 한글 이름 | 문서 | 내부 코드 | `DocKind` |
| --- | --- | --- | --- |
| 계약서 | 서비스·기타 계약서 (기본값) | CTR | `contract` |
| 민간임대주택 표준임대차계약서 (등록임대사업자) | 국토부 별지 제24호서식 | CTR | `contract` / `mlt_standard` |
| 주택임대차표준계약서 | 법무부·국토부 표준서식 | CTR | `contract` / `housing_standard` |
| 임대차 계약서 | 자체 서식 | CTR | `contract` / `general` |
| 서명계약서 | 전자서명 완료본 | SGN | `signed_contract` |
| 청구서 | 인보이스 / 세금계산서 | INV | `invoice` |
| 영수증 | 영수증 | RCP | `receipt` |
| 견적서 | 견적서 | QUO | `quote` |
| 세대점검표 | 입주·퇴거 점검표 (한 장) | INS | `inspection` |
| 퇴거 세대 확인서 | 보증금 정산 | STL | `settlement` |
| 신청서 | 홈스테이·단기 체류 신청서 | APL | `application` |
| 작업지시서 | 작업지시서 | WOR | `work_order` |
| 서비스브리프 | 파트너 브리프 | BRF | `brief` |
| 리포트 | 운영 리포트 | RPT | `report` |
| 서식샘플 | 서식 샘플 / 빈 양식 | SMP | `sample` |
| 기타서류 | 그 외 | DOC | `other` |

종류 하나에 이름이 여럿인 것은 **임대차 계약서뿐**이다. 서식을 파일명으로
가려야 하므로 라우트가 `variant`로 서식 키를 넘기고 `DOC_NAME_VARIANTS`가
정식 명칭을 돌려준다. 계약서 뒤에 붙는 별지·동의서(별지 특약사항, 보증금
동의서, 임차인 확인서·확약서, 계약갱신 거절통지서)는 계약서 PDF에 병합되어
나가므로 **자체 파일명을 갖지 않는다**.

3자리 코드는 파일명에서 빠졌지만 내부 키로 남는다 —
`document_file_names.doc_code`와 옛 발행본 해석에 쓰인다. 새 문서를 추가할
때는 `DOC_CODES`와 `DOC_NAMES_KO` **둘 다** 등록한다.

## 5. 리포트 파일명

정산·수수료·캠페인처럼 특정인에게 발행되지 않는 **운영 리포트**는 §4의 사본번호
카운터를 쓰지 않는다. 대상·종류·기준일·버전으로 이름이 정해지고, 여기서는
**첫 판부터 `_v1`**이 붙는다 — 리포트는 재발행이 기본값이기 때문이다.

```
리포트-[대상]-[리포트종류]-[기준일 YYYYMMDD]_v[버전].<확장자>

리포트-에이치케이건설자산관리-월별정산-20260731_v1.pdf
리포트-여수_메트하임-공실현황-20260731_v1.csv
리포트-전체-캠페인성과-20260731_v2.csv
```

- **대상** — 법인 상호·건물명·에이전트명. 비우면 **발행사 상호**가 들어가고,
  그것도 없으면 `전체`.
- **리포트종류** — 통제 어휘(`REPORT_TYPES`)만 쓴다: `월별정산` `보증금정산`
  `커미션명세` `공실현황` `매출현황` `미납현황` `유지보수현황` `하자청구명세`
  `파트너정산` `캠페인성과` `서류점검표` `예약현황`
- **버전** — `v1`부터. 재발행본은 덮어쓰지 않고 버전을 올린다.

서버는 `buildReportFileName()`, 관리자 화면의 표 내려받기는
[csv.ts](../artifacts/property-admin/src/lib/csv.ts)의 `csvFileName()`이 같은
규칙을 쓴다.

## 6. 인스턴스 스위치 — 한글 이름 + 회사 상호

기본값은 상대 이름 하나만이다. 아래를 켜는 인스턴스만 이름이 길어진다.

| 환경변수 | 효과 |
| --- | --- |
| `PARTY_CODE_PREFIX=MH` | 고객ID 접두사 (미설정 시 `MS`). **폴더명에만** 쓰인다 |
| `DOC_NAME_INCLUDE_ORG=1` | 거래처 **담당자 한글 이름 + 법인 상호**를 함께 남긴다 → `홍길동_재원산업` |
| `DOC_NAME_ISSUER_LABEL=…` | 리포트 대상 필드의 발행사 표기 (미설정 시 조직 설정의 상호) |
| `VITE_DOC_ISSUER_LABEL=…` | 관리자 화면 CSV의 발행사 표기 (미설정 시 `VITE_APP_NAME`) |

**Metheim은 `PARTY_CODE_PREFIX=MH` + `DOC_NAME_INCLUDE_ORG=1`을 켠다.** 발행사
상호는 발행 문서명에 넣지 않는다 — 받는 쪽이 여는 파일에 보내는 쪽 이름을
반복할 이유가 없다. 발행사 표기가 필요한 곳은 상대가 없는 운영 리포트뿐이고,
거기서 `DOC_NAME_ISSUER_LABEL`이 대상 필드로 들어간다.

계정명만으로는 법인 상호인지 사람 이름인지 알 수 없어서, `DOC_NAME_INCLUDE_ORG`가
켜지면 계정의 대표 연락처를 한 번 더 읽어 담당자 이름을 확보한다
(`accountPartyNames()`). 개인 임차인처럼 사람 이름과 계정명이 같으면 하나로
접힌다 — `김용식_김용식`은 나오지 않는다.

발행사 상호는 조직 설정(Settings → Organisation)의 `trading_name`을 쓰고 60초
캐시한다. 상호가 길면 `DOC_NAME_ISSUER_LABEL`로 짧게 잡는다.

## 7. 검증

```
고객ID     ^[A-Z]{2}[0-9]{4}[CB]([0-9]{3}|[A-Z][0-9]{2})$
발행 문서   ^[이름]-[서류이름]_[0-9]{8}(-v[0-9]{1,3})?$
리포트      ^[필드]-[필드]-[필드]-[0-9]{8}_v[0-9]{1,2}$
옛 형식 1   ^([필드]-){1,3}[필드]-[0-9]{8}([A-Z][0-9]?|Z9-[0-9]+)?$   (~2026-08-16)
옛 형식 2   ^[A-Z]{3}-[필드](-[필드])?_[0-9]{8}([A-Z][0-9]?)?$        (~2026-08)
```

`[이름]`은 `-`가 없고 `_`로만 이어지는 덩어리, `[서류이름]`은 `-`·`_`가 없는
(공백은 되는) 덩어리, `[필드]`는 `-`와 공백이 없는 한 덩어리다. 정규식 원본은
`PARTY_CODE_RE` / `DOC_FILE_NAME_RE` / `REPORT_FILE_NAME_RE` /
`LEGACY_DOC_FILE_NAME_RE` / `LEGACY_CODE_FILE_NAME_RE`이고,
`isValidDocFileName()`과 `parseDocFileName()`이 그 위에 있다. 파서는 이름만으로
상대·서류종류·발행일·사본번호를 되돌려주며, **옛 형식 두 가지도 계속 읽는다** —
이미 나간 파일은 리네임하지 않는다.

## 8. 구현 규칙

- 이름은 `resolveDocFileName()` **하나로만** 만든다.
- PDF 응답은 `setDocFileName(res, baseName)`으로 헤더를 세운다. 한글이 들어가므로
  `Content-Disposition`은 RFC 5987 형식이 필수이고, 프론트가 blob으로 받아
  저장할 수 있도록 `X-Document-Filename`을 함께 실어 보낸다(CORS 노출은
  `app.ts`의 `exposedHeaders`).
- 프론트(`DocumentPreviewDialog`)는 이 헤더가 있으면 그것을 다운로드 이름으로
  쓴다. 호출부의 `filename`은 헤더가 없을 때의 폴백일 뿐이다.
- **이름은 문서당 한 번만 정해진다.** PDF는 미리보기·다운로드·이메일마다 다시
  렌더되므로 매번 사본번호를 새로 뽑으면 같은 청구서가 `-v2`였다가 `-v3`이
  된다. 최초 발행 시 `document_file_names`에 기록하고 이후에는 읽어 쓴다.
  같은 행의 `party_key`가 사본번호 카운터의 키(`이름|서류이름`)를 담는다.
- 파일명 할당이 실패해도 **문서 발행은 막지 않는다** — 사본번호 없는(=첫
  발행본과 같은 모양의) 규칙에 맞는 이름으로라도 나간다.

## 9. 적용 범위와 운영

- **적용** — 서버가 렌더해 내보내는 모든 문서(미리보기/다운로드/이메일 첨부),
  발행본 스냅샷(`freezeDocument` — 첫 판은 표기 없음, 2판부터 `…-v2.pdf`),
  관리자 화면의 표 내려받기(CSV).
- **미적용** — 사무실에서 업로드한 스캔본·회사 서류. 받은 파일의 원래 이름이
  곧 추적 단서라 **물리 파일명을 바꾸지 않는다.** 대신 `documents`의 색인
  컬럼(`title`·`doc_date`·`doc_year`·`tags`)으로 찾는다.
- 업로드 인박스의 파일명 판독기([intakeScan.ts](../artifacts/api-server/src/lib/documents/intakeScan.ts))는
  이 규칙을 알고 있다. 우리가 발행했다가 서명받아 다시 올라온 문서는
  `parseDocFileName()`으로 서류종류·이름·날짜를 그대로 읽어낸다(신뢰도 0.8).
- **AI 자동 확정은 하지 않는다.** 판독 결과는 사람이 검토 큐에서 확인한 뒤에만
  레코드에 붙는다.
- 서식 샘플·빈 양식은 발행 대상이 없으므로 사본번호를 소비하지 않는다
  (`서식샘플-<서식키>_<locale>`).
- **2026-08-16 이전 발행본은 그대로 둔다.** 옛 이름(`MH2607C001-김용식-계약서-
  20260803A`, `CTR-김용식_20260803A`)은 `document_file_names`에 고정 저장되어
  있어 같은 문서를 다시 열어도 이름이 바뀌지 않는다. 새 규칙은 그날 이후 처음
  발행되는 문서부터 적용된다.
